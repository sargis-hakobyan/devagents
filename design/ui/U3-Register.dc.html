An existing Git checkout, by the absolute path the service can see. Nothing is cloned, copied or mounted for you; work happens in managed worktrees and the checkout is never modified.

New project
What registration checks. The path exists, is readable by the service, is the root of a Git repository with at least one commit, and does not resolve elsewhere through a symlink. The base commit is recorded. No file inside the checkout is read or written.
Sends POST /projects with the session's CSRF token. Your input stays in the form if the service refuses it.
Running in Docker? Mount first, then register the container path
1
Mount the checkout explicitly in compose.override.yaml. Home directories and the Docker socket are never mounted, and there is no filesystem browser.
services:
  devagents:
    volumes:
      - /Users/you/Projects/website:/projects/website
2
Restart the service so the mount exists: ./devagents start
3
Register the container path here (/projects/website), or from the terminal:
docker compose exec devagents node dist/cli/main.js projects add website /projects/website
Host ↔ container: /Users/you/Projects/website on your Mac is /projects/website inside the service. Tasks report container paths; commits land on branches in your real checkout through the mounted worktree.

Invalid path (Docker)
Not a Git repository the service can see. /Users/you/Projects/website does not exist inside the container. Mount the checkout in compose.override.yaml, restart, then enter its container path such as /projects/website.
Conflict
Project ID website is already registered for /projects/website. Choose another ID, or open the existing project. A path registered under two IDs is also refused.

Other backend refusals, rendered as the service states them
  • Not a Git root · /projects/website/src is inside a repository; register /projects/website.
  • No commits yet · create an initial commit first; worktrees branch from a base commit.
  • Path resolves elsewhere · the path is a symlink to a location outside what the service may use.
  • Not readable · permission denied for the service user (Docker runs as a non-root user).
