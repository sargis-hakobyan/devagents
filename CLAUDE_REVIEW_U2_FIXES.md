## Remaining limitations and open items from the review

- **Model pinning** is unchanged by instruction: `model: default` stays an unpinned runtime choice recorded as `modelPinned: false`; a configured `defaultModel` or member override is required for a fully pinned snapshot.
- **Unsupported capability drafts** remain the deliberate behaviour: such members save as non-executable drafts; the runtime fails closed. The acceptance wording in the implementation plan now says so.
- **Mode-default idempotency** is a pre-existing exception not addressed here: `defaultMode` is resolved before the request fingerprint, so a byte-identical retry without a mode conflicts after `config.defaultMode` changes. Fingerprinting caller intent before resolving defaults is a follow-up that must stay compatible with existing request records.
- **Disabled members with unavailable engines/providers/capabilities** still block readiness; they must be corrected or removed, not merely disabled. Documented, not changed.
